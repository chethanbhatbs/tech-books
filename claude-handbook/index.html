What is Claude

What Claude is, what it can do for you, and where you can use it.

Claude is an AI assistant made by Anthropic. You type or speak a request in plain English. Claude writes, explains, plans, summarises, reads your files, and writes code.

Where you can use it

WhereGood forPlan needed
Website: claude.aiChat from any browserFree works
Desktop app (Mac, Windows)Chat, plus a Code tab for codingFree works for chat
Phone app (iOS, Android)Chat on the goFree works
Claude Code (terminal, VS Code, JetBrains, web)Building and fixing softwarePro, Max, Team or Enterprise

The Claude models

A model is the brain that writes the answer. Bigger models think harder. Smaller models answer faster.

ModelIn plain words
Claude Fable 5.1The most capable. For the hardest thinking and long, multi-step jobs. Slowest.
Claude Opus 5.5Very strong at long coding and knowledge work.
Claude Sonnet 5.5The everyday balance of speed and smarts.
Claude Haiku 5.5The fastest and lightest. Good for quick, simple tasks.

You pick the model from a menu near the message box. If you're not sure, keep the default.

Plans and usage limits

Which plan fits you, what each one adds, and how usage limits reset.

Claude has a free plan and several paid ones. Paid plans add Claude Code, Cowork, Research and much more usage. Prices below were checked on 23 Oct 2026; confirm them on claude.com/pricing before you buy.

PlanPrice (US$ a month)Who it's forAdds
Free0Trying ClaudeChat on web, desktop and phone, web search, file creation, memory, Artifacts, connectors
Pro20 monthly, 17 a month billed yearlyOne person, regular useClaude Code, Cowork, Research, more models, Claude in Chrome
Max100 (5x Pro's usage) or 200 (20x)Heavy daily useEverything in Pro, much more usage, priority access
Team25 a seat monthly, 20 yearly; Premium seats cost moreSmall teamsShared projects, admin controls, single sign-on
EnterprisePer seat plus usage, through salesLarge organisationsAudit logs, custom data retention, role-based access

How usage limits work

  • A session limit that resets every five hours, and a weekly limit that resets once a week.
  • What you use depends on the length of the chat, the files you attach, the features (Research uses more), the model and the effort level.
  • To make your usage go further: start a new chat for a new topic, attach only the files you need, and use a lighter model for simple jobs.

Install the desktop app

Install the Claude desktop app on a Mac or Windows PC and sign in.

Check your computer first: macOS 13 or newer, or Windows 10 (version 1809) or newer. A Linux version is in beta.

  1. Download the installer: Claude for Mac. One file works on Intel and Apple-chip Macs.
  2. Open the downloaded .dmg file and drag Claude into Applications.
  3. Open Claude from Applications.
  4. Sign in with your Claude account, or create one.
  5. Type your first message.
  1. Download the installer: Claude for Windows. An ARM64 build also exists.
  2. Run the downloaded .exe file and follow the prompts.
  3. Open Claude from the Start menu.
  4. Sign in with your Claude account, or create one.
  5. Type your first message.
The Code tab. The desktop app has a Code tab that runs Claude Code without a terminal. You choose a folder, pick a model, and describe the task. The Code tab needs a Pro plan or higher.

Your first chats

Write your first prompts and see what a good one looks like.

A good prompt has three parts. Say what you need, give the background, and say what the answer should look like. The weak prompt below has only the first part. The better prompt has all three.

PartWeak promptBetter prompt
The task"Write an email.""Write an email asking my manager for Friday off."
The backgroundMissing, so Claude has to guess"I finished the report early. Keep it polite and short."
The shapeMissing, so Claude picks any length"Under 80 words, with a subject line."

Prompts to try today

  • "Summarise this PDF in 5 bullets." (attach the file)
  • "Make a weekly meal plan for two, as a table."
  • "Explain this error message in simple words."
  • "Ask me 5 questions, then write my cover letter."
Check the important facts. Claude can be wrong. For money, health or legal questions, check the answer with a trusted source.

Prompting well

Six habits that turn a vague request into a useful answer.

Anthropic's own advice comes down to one idea: treat Claude like a brilliant new colleague who knows nothing about your situation. If a colleague would be confused by your request, Claude will be too.

HabitWeakBetter
Be clear and direct"Fix this email.""Make this email shorter and more polite. Keep the deadline of 3 May."
Say why"No jargon.""No jargon: the readers are parents, not engineers."
Say what the answer should look like"Compare these phones.""Compare these phones in a table: price, battery, camera. Then one line on which to buy."
Show an example"Write product descriptions.""Write descriptions like this one: [example]. Same length and tone."
Give it a role"Check my contract.""You are a careful contracts lawyer. List the clauses that could cost me money."
Put long documents firstQuestion, then a 40-page reportThe report first, your question at the end

Two more tricks

  • Label the parts of a long prompt with tags such as <instructions>, <context> and <document>, so Claude knows which text is which.
  • Steps in order: when the order matters, write the steps as a numbered list.
Not happy with an answer? Don't start again. Say what was wrong: "Too long, and drop the last section." Claude keeps the conversation in mind.

Projects

Keep files, instructions and chats for one piece of work together.

A project is a workspace for one piece of ongoing work, such as a course, a client or a book. It keeps its own chats, its own files and its own instructions, so you don't have to explain the background every time.

  1. In the sidebar, open Projects and click New project. Give it a name.
  2. Add project knowledge: upload the documents Claude should know, such as a style guide or a syllabus. Each file can be up to 30 MB.
  3. Write project instructions, for example "Answer as a tutor for first-year students. Short answers, one example each."
  4. Start chats inside the project. Every chat sees the files and follows the instructions.
FactDetail
MemoryEach project has its own memory, kept apart from your other chats
Lots of filesOn paid plans, a project can hold much more than one chat can, because Claude searches the files for what it needs
SharingOn Team and Enterprise, share a project with colleagues as "Can view" or "Can edit"

Artifacts

Get documents, charts, diagrams and small apps you can share.

An artifact is something Claude makes for you to use or show someone: a document, a slide deck, a chart, a diagram, a web page or a small working app. It opens in a panel beside the chat, where you can view it, change it and share it.

Ask forYou get
"Make a one-page study plan for my exams."A document you can edit and download
"Turn this data into a bar chart."A chart
"Draw a flowchart of our hiring process."A diagram
"Build a quiz with ten questions on photosynthesis."A small interactive app
  • Private first. An artifact is visible only to you until you share it. Sharing gives it its own link.
  • AI-powered artifacts can use Claude themselves, so the people using them can ask questions or get feedback.
  • Turn it on. Artifacts need Settings → Capabilities → Code execution and file creation.

Privacy and your data

Decide whether your chats train Claude, and how long data is kept.

On Free, Pro and Max, you choose whether your chats help train Claude. Team and Enterprise work differently.

QuestionAnswer
Where is the setting?Settings → Privacy → Help improve our AI models
If I turn it off?New chats and coding sessions aren't used for training. Chats are kept for 30 days.
If I leave it on?Chats may be used to train models and kept for up to 5 years, with personal details removed.
Deleted chats?Gone from your history at once, and from Anthropic's systems within 30 days.
Incognito chats?Kept for 30 days, then deleted.
Team and Enterprise?Not used for training by default. Enterprise can set its own retention period.
Good habit. Don't paste passwords, card numbers or other people's private details into any AI chat, whatever the settings.

Which Claude to use

Chat, Claude Code or Cowork: pick the one that fits the job.

Claude comes in three products, and each fits a different kind of work. Pick by what you want at the end, not by habit.

  1. Claude app (chat). Web, desktop or phone. You steer every reply. Claude works only inside the chat unless you add connectors.
  2. Claude Code. Reads your code, edits files and runs commands. Runs in a terminal, the desktop app's Code tab, VS Code, JetBrains or the web. The terminal is a hurdle if you've never used one. Paid plans only.
  3. Cowork. A tab in the Claude desktop app (Mac and Windows), plus cloud sessions. You describe the outcome and review at the end, so give clear instructions and only the folders it needs. Paid plans only.

Try it: which one fits?

Answer three questions to see which one fits your task.

Claude Code in the terminal

Install Claude Code, start it in a project, and learn the first commands.

Claude Code is Claude for building software. Claude Code reads the files in a folder, edits them, and runs commands. Before risky steps, Claude Code asks you first.

You need: a Pro, Max, Team or Enterprise plan, 4 GB of memory or more, and an internet connection. The Free plan does not include Claude Code.

Open a terminal

ComputerHow
MacPress Cmd + Space, type Terminal, press Enter.
WindowsClick Start, type PowerShell, press Enter.

Install

curl -fsSL https://claude.ai/install.sh | bash
irm https://claude.ai/install.ps1 | iex

Also install Git for Windows. Claude Code works best with it.

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Homebrew and WinGet work too: brew install --cask claude-code or winget install Anthropic.ClaudeCode.

Start and sign in

  1. Go to a project folder: cd Documents/my-project
  2. Type claude and press Enter.
  3. A browser window opens. Sign in with your Claude account.
  4. Back in the terminal, ask: "What does this project do?"

Commands worth knowing

TypeWhat it does
/helpShows every command.
/Lists commands and skills.
/clearStarts a fresh conversation.
/code-reviewReviews your changes.
/mcpShows connected MCP servers, their status, and sign-in.
/pluginFinds and installs plugins.
/exitLeaves Claude Code.

Update and uninstall

The standard install updates itself. For Homebrew or WinGet, run brew upgrade claude-code or winget upgrade Anthropic.ClaudeCode. To uninstall on Mac or Linux:

rm -f ~/.local/bin/claude
rm -rf ~/.local/share/claude
No terminal? Claude Code also runs in the desktop app's Code tab, in VS Code and JetBrains editors, and on the web at claude.ai/code.

Effort, modes and context

Set how hard Claude thinks, how much it may do alone, and what it holds in mind.

Three controls decide how Claude Code works on a task: effort (how hard Claude thinks), permission mode (how much it may do without asking) and the context window (how much it can hold in mind at once).

Effort levels

Effort sets how much Claude thinks on each step. More effort means deeper reasoning, but slower answers and more tokens used, so more of your plan's usage or a higher bill. Drag the slider to compare the levels.

Try it: drag the slider

Thinking depth
Speed
Token use

The bars show the direction of each change. They are not measurements.

How to set itWhat it does
/effortOpens a slider. Press Enter to save it as your default, or s for this session only.
/effort highSets a level directly. /effort auto goes back to the model's default.
claude --effort highStarts a session at that level.
ultrathinkPut this word anywhere in a prompt for deeper thinking on that one turn. Your effort setting stays the same.
effort: highIn a skill's or subagent's frontmatter. That skill or subagent runs at that level.

The default is medium on Opus 5.5, Sonnet 5.5 and Haiku 5.5, and high on most other models, including Fable 5.1. On these newer models thinking can't be switched off. Effort decides how much of it happens.

Permission modes

Press Shift+Tab to move through the modes. The current mode shows at the bottom of the screen.

ModeWhat Claude may do without askingUse it when
defaultRead files. It asks before editing a file or running a command.You want to review every action.
acceptEditsRead and edit files, and run common file commands.You trust the task and will review the changes at the end.
planRead and explore, then write a plan. No edits until you approve the plan.A big or unclear change. Agree on the approach first.
autoEverything, with safety checks running in the background. Shown only where available.Long tasks where stopping to ask would slow you down.

The context window

The context window is Claude's working memory for one conversation. It holds your messages, the files Claude has read, command output, your CLAUDE.md and the one-line descriptions of your skills. When it fills up, older detail gets squeezed out.

TypeWhat it does
/contextShows what is filling the window right now, by category.
/compactSummarises the conversation to free space. Claude Code also does this by itself when the window is nearly full.
/clearStarts a fresh conversation in the same folder. Use it between unrelated tasks.

Everyday workflows

The everyday loop, and the prompts that start the common jobs.

Most good sessions follow the same shape: understand, plan, change, check, save. The diagram shows the loop. The table gives the prompts that start each common job.

  1. Explore. Ask Claude to read the relevant code and explain it. No edits yet.
  2. Plan. Switch to plan mode (Shift+Tab or /plan). Claude proposes the change. You read it and approve, or ask for changes.
  3. Change. Claude edits the files. In default mode you approve each edit.
  4. Check. Claude runs the tests or the app. If something fails, it goes back to step 3.
  5. Save. Claude commits, and can open a pull request for review.
JobA good first prompt
Understand a new codebase"Give me an overview of this project, then walk me through how a request reaches the database."
Fix a bug"Here is the error: [paste]. Find the cause, explain it, then fix it and add a test that fails without the fix."
Test first"Write failing tests for a discount rule: 10% off orders over 100. Don't write the code yet." Then: "Now make the tests pass."
Build a featureStart in plan mode: "Plan how to add CSV export to the reports page. List the files you'll change."

The five layers

The five layers that shape Claude Code, and the problem each one solves.

Claude Code's features stack in five layers. Each layer fixes a problem that a better prompt can't. The lower layers are the foundation, and each layer up gives you more control. Click a box to see its file, when it loads, and an example.

  1. CLAUDE.md, the memory layer. Standing project rules and conventions. Loaded in full at the start of every session.
  2. Skills, the knowledge layer. Steps, checklists and templates for a repeat job. Only the one-line description loads at the start. The full steps load when the task matches or you type /name.
  3. Hooks, the guardrail layer. Your own script, run every time a set event happens, such as before or after a tool. A rule in CLAUDE.md is advice Claude may miss. A hook always runs.
  4. Subagents, the delegation layer. A helper with its own context window and tool list. It does a side job and returns a summary. Subagents can start their own, up to three levels deep.
  5. Plugins, the distribution layer. A bundle of skills, subagents, hooks and MCP servers. One install gives the whole team the same setup.
  6. MCP servers. Not a layer of behaviour but the connection to the real world: issue trackers, web APIs, databases, files. Any layer can use the tools they add.

Check yourself: which layer?

Each question is a real problem. Pick the layer that solves it.

Skills

Save the steps for a job you repeat, so Claude follows them every time.

Think of a skill as a recipe card. Without one, you explain the same job to Claude every time: which file to read, what headings to use, how long to make it. With a skill, you write those steps once, and Claude follows them whenever that job comes up.

A skill is a folder with one file in it, SKILL.md. The top of the file holds a name and a one-line description. The rest holds the steps.

# .claude/skills/weekly-report/SKILL.md
---
name: weekly-report
description: Write my weekly status report. Use when I ask for a weekly update.
---
1. Read the notes in reports/notes.md.
2. Group the items under Done, In progress and Blocked.
3. Keep it under 200 words, in plain English.
StepWhat happens
1. You save the skillClaude Code sees only the skill's name and description. The steps stay unread, so they cost almost nothing.
2. You ask for the job"Write my weekly update" matches the description, so Claude opens the skill and reads the steps.
3. Claude follows the stepsSame headings, same length, every week.
Or: you call it by nameType /weekly-report. Text after the name reaches the skill as $ARGUMENTS.

Hooks

Run your own script at set moments, for rules that must never be skipped.

A hook is your own script that Claude Code runs at a set moment, every time, whatever Claude decides. Use hooks for rules that must never be skipped.

  1. SessionStart. The session begins or resumes. Good for loading context, such as today's tickets.
  2. UserPromptSubmit. You send a prompt, before Claude sees it. Can add context or block it.
  3. PreToolUse. Claude is about to use a tool. Your script can block it, for example any edit to .env.
  4. The tool runs. The edit, command or search happens.
  5. PostToolUse. The tool finished. Good for running the formatter or the linter.
  6. Stop. Claude has finished its answer. Good for a final check or a notification.
# .claude/settings.json: block every edit to .env files
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
        "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/protect-env.sh" }]
    }]
  }
}
# .claude/hooks/protect-env.sh
#!/bin/sh
# Claude Code sends details of the tool call as JSON on stdin
path=$(jq -r '.tool_input.file_path')
case "$path" in
  *.env|*.env.*) echo "Editing $path is not allowed" >&2; exit 2 ;;
esac
exit 0
Exit codeMeaning
0Carry on
2Block. What the script prints to stderr is shown to Claude as the reason.

Type /hooks to see the hooks that are set up.

Permissions and safety

Decide what Claude may do without asking, and stay safe.

Permission rules decide what Claude Code may do without asking. They live in settings.json under permissions, as three lists: allow, ask and deny.

# .claude/settings.json
{
  "permissions": {
    "allow": ["Bash(npm run test *)", "WebFetch(domain:docs.python.org)"],
    "ask":   ["Bash(git push *)"],
    "deny":  ["Read(./.env)", "Read(./secrets/**)", "Bash(curl *)"]
  }
}
RuleMatches
Bash(npm run test *)Any command starting with npm run test
Read(./.env)Reading that one file
EditEvery file edit (a bare tool name matches all uses)
WebFetch(domain:docs.python.org)Fetching pages from that site
mcp__github__create_issueOne tool from one MCP server

Order: deny is checked first, then ask, then allow. A deny rule always wins, and an allow rule can't make an exception to it. Type /permissions to see and edit the rules.

Stay safe

  • Treat what Claude reads as untrusted. A web page, issue or file can hide instructions aimed at the model. This is called prompt injection.
  • Deny reads of secrets, such as .env files and key folders.
  • Keep asking on for risky commands: pushes, deletes, deploys, anything that spends money.
  • Use the sandbox. /sandbox limits which files and network addresses shell commands can reach (macOS, Linux and WSL2).
  • Install only plugins and MCP servers you trust.

MCP: the parts

The host, the client and the server, and how they talk.

MCP (Model Context Protocol) is an open standard for connecting AI apps to tools and data. MCP has three roles.

RoleWhat it doesExample
HostThe AI app you use. The host holds the chat, talks to the model, and asks your permission.Claude Code, Claude Desktop, claude.ai, your own app
ClientA connector inside the host. The host runs one client per server.Built into the host
ServerA small program that offers tools and data to any MCP host.A GitHub server, a files server, your own server

What a server can offer

PrimitiveMeaningExample
ToolsActions Claude can ask to runcreate_issue, weather_current
ResourcesData Claude can readA file, a database row
PromptsReady-made prompt templates"Review this pull request"

How the messages travel

Every message is JSON-RPC 2.0, a simple JSON format for requests and replies. Two transports carry the messages:

TransportWhen
stdioThe server runs on the same computer as the host. The host starts the server as a child program and they talk through standard input and output.
Streamable HTTPThe server runs somewhere else and is reached over the internet. The older HTTP + SSE transport is deprecated.

The current spec is dated 2026-07-28: modelcontextprotocol.io/specification.

How a tool is defined

What a tool definition contains, field by field.

A tool is a small JSON description. The server writes the description, and the model reads it to decide when and how to use the tool. A clear description matters as much as the code behind it.

# a tool definition, as the server sends it in tools/list
{
  "name": "weather_current",
  "title": "Weather Information",
  "description": "Get current weather for any location worldwide",
  "inputSchema": {
    "type": "object",
    "properties": {
      "location": { "type": "string", "description": "City name or coordinates" },
      "units": { "type": "string", "enum": ["metric", "imperial"], "default": "metric" }
    },
    "required": ["location"]
  }
}
FieldRequiredWhat it is for
nameYesThe ID the model uses to call the tool. Letters, numbers, _ and -, up to 128 characters.
descriptionYesPlain words telling the model what the tool does and when to use it.
inputSchemaYesA JSON Schema for the inputs: names, types, which are required.
titleNoA friendly name to show people.
outputSchemaNoThe shape of the result, if the tool returns structured data.
annotationsNoHints about behaviour, such as whether the tool only reads.

The two calls

# host → server: run the tool
{ "jsonrpc": "2.0", "id": 7, "method": "tools/call",
  "params": { "name": "weather_current", "arguments": { "location": "Pune" } } }
# server → host: the result
{ "jsonrpc": "2.0", "id": 7,
  "result": { "content": [ { "type": "text", "text": "24°C, cloudy" } ], "isError": false } }

tools/list asks a server for all its tool definitions. tools/call runs one tool. If the tool fails, the result carries "isError": true and a message the model can read.

MCP vs API

When to build an MCP server, and when to call the API with tools.

An API is one service's own set of URLs and rules. MCP is one shared plug shape that any AI app can use for any tool. An MCP server usually calls a service's API underneath. So MCP does not replace APIs. MCP wraps APIs in a form AI apps can discover and use.

APIMCP
What it isOne service's interfaceOne standard for AI apps to find and use tools
Built forAny programAI apps and models
How tools are foundA developer reads the docs and writes codeThe host asks tools/list while running, and the model reads the descriptions
Work per new appNew code for every serviceNone, if the app speaks MCP
Who decides what to callThe developer's codeThe model, with the host's permission

Tools in the Claude API, without MCP

The Claude API has its own tools parameter. The flow is the same as MCP: Claude replies with a tool_use block, your code runs the tool, and you send back a tool_result block. The only difference is that your code holds the tools, with no MCP server involved. The schema field is spelled input_schema in the API and inputSchema in MCP.

Save money and get reliable output

Cut API cost with caching and batches, and get JSON you can trust.

Three API features cut cost or make answers easier to use in code.

Prompt caching

If every request starts with the same long text, such as a manual or a big system prompt, mark it for caching. Later requests read it from the cache at a fraction of the price.

# mark the long, unchanging part
"system": [{
  "type": "text",
  "text": "...a long product manual...",
  "cache_control": {"type": "ephemeral"}
}]
FactDetail
How long it lasts5 minutes by default, or 1 hour if you ask for it
Writing to the cache1.25 times the normal input price (2 times for the 1-hour cache)
Reading from the cacheA small share of the input price: 5% on Opus 5.5 and Sonnet 5.5, 2.5% on Fable 5.1
What breaks itChanging anything before the marked point, such as the tools or the system prompt

Message Batches

For work that doesn't need an answer right now, send up to 100,000 requests in one batch. Batches cost 50% less. Most finish within an hour, and every batch finishes within 24 hours. Good for evaluations, tagging and bulk summaries.

Structured outputs

When your code needs JSON, give the API a JSON Schema. The answer is guaranteed to match it, so you don't have to check and retry.

# Python, with a Pydantic model as the schema
from pydantic import BaseModel

class Contact(BaseModel):
    name: str
    email: str

result = client.messages.parse(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Extract the contact: Asha Rao, asha@example.com"}],
    output_format=Contact,
)
print(result.parsed_output.email)

Connect your own app

Connect your own app to Claude, through MCP or the API.

"Connecting your app to MCP" means one of two things. Pick the path that matches your goal.

Path 1. Let Claude use your app: build an MCP server

  1. Write a server that wraps your app's actions as tools. The Python SDK keeps a small server very short:
# server.py, using the official Python SDK (pip install mcp)
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("weather")

@mcp.tool()
def weather_current(location: str) -> str:
    """Get current weather for a city."""
    # call your real API or database here
    return f"24°C, cloudy in {location}"

if __name__ == "__main__":
    mcp.run()  # stdio

The SDK turns the function name, the docstring and the type hints into the tool's name, description and inputSchema. A TypeScript SDK also exists: @modelcontextprotocol/sdk.

  1. Test the server with the MCP Inspector, which lists your tools and lets you call them by hand.
  2. Add the server to Claude Code: claude mcp add weather -- uv run server.py
  3. To use the server in claude.ai, run it over Streamable HTTP on a public URL, add OAuth, and add the URL as a custom connector.
stdio servers must not print. On stdio, standard output carries the JSON-RPC messages. A stray print() breaks them. Log to standard error instead.

Path 2. Use Claude inside your app: call the API with tools

# your app, using the Anthropic Python SDK
import anthropic
client = anthropic.Anthropic()

tools = [{
    "name": "weather_current",
    "description": "Get current weather for a city",
    "input_schema": {"type": "object",
                     "properties": {"location": {"type": "string"}},
                     "required": ["location"]}
}]

msg = client.messages.create(
    model="claude-sonnet-5-5", max_tokens=1024, tools=tools,
    messages=[{"role": "user", "content": "Weather in Pune?"}])

# msg.content holds a tool_use block. Run the tool yourself,
# or forward it to an MCP server with tools/call, then send
# the output back as a tool_result block in the next request.

To use existing MCP servers here, make your app an MCP client with the MCP SDK. Call tools/list, pass those tools to Claude, and turn each tool_use into a tools/call.

Claude Code in CI and GitHub

Run Claude Code in scripts and CI, and from @claude on GitHub.

Claude Code can run without a chat window, inside scripts and CI jobs. On GitHub, you can mention @claude in an issue or pull request and it does the work there.

In a script

# answer once and exit; JSON is easy for scripts to read
claude -p "Summarise what changed in the last 5 commits" --output-format json
cat build.log | claude -p "Why did this build fail?"

On GitHub

  1. In Claude Code, run /install-github-app. It installs the GitHub app and adds the secret. It needs the GitHub CLI signed in.
  2. A workflow file using anthropics/claude-code-action@v1 is added to .github/workflows/.
  3. Comment "@claude fix the failing test" on a pull request. Claude works in the action and pushes its changes.
# .github/workflows/claude.yml (the core of it)
on:
  issue_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions: { contents: write, pull-requests: write, issues: write, id-token: write }
    steps:
      - uses: actions/checkout@v6
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}

Build your own agent: the Agent SDK

Build your own agent on the engine Claude Code runs on.

The Claude Agent SDK gives your program the same engine Claude Code runs on: the agent loop, the built-in tools (read, edit, run commands, search), permissions, hooks, subagents and MCP. You write the program; the SDK does the agent work.

LanguageInstall
Pythonpip install claude-agent-sdk
TypeScriptnpm install @anthropic-ai/claude-agent-sdk
# Python: an agent that fixes bugs in one file
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions

async def main():
    async for message in query(
        prompt="Find the bugs in utils.py and fix them",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Edit", "Glob"],
            permission_mode="acceptEdits",
        ),
    ):
        print(message)

asyncio.run(main())
SDK or API? Use the API (chapter A6) when you want one answer to one request. Use the Agent SDK when the job takes many steps with tools, the way Claude Code works.

Security checklist for tools

  • Give each server the smallest access that works, such as read-only tokens.
