Chapter 0

What is a web page?

Before any code: what a web page is, and the three languages every page is made of.

A web page is a text file

A web page is a text file that a browser turns into what you see.

The file is plain text with labels in it, saved with a name that ends in .html. The browser (Chrome, Safari, Firefox, Edge) reads the labels and draws headings, paragraphs, links and pictures.

Four words you will hear

WordPlain meaningExample
Browserthe app that shows web pagesChrome, Safari, Firefox, Edge
Servera computer somewhere that stores web pages and sends them when askedthe computer behind a website
URLthe address of a pagehttps://example.com/about.html
Websitea group of pages that link to each othera shop's home, products and contact pages

Three languages, three jobs

Almost every page uses three languages together. This book is about the first one.

LanguageIts jobLike in a house
HTMLwhat is on the page, and what each part is: a heading, a paragraph, a linkthe walls and rooms
CSShow it looks: colours, sizes, where things sitthe paint and furniture
JavaScriptwhat it does: reacts when you click or typethe switches and wiring

The three jobs are from MDN: HTML "defines the meaning and structure of web content", CSS describes "appearance/presentation", JavaScript "functionality/behavior". The house is only a way to remember it.

Source: MDN: HTML

You do not need a server to learn

A .html file on your own computer opens straight in the browser. No server, no internet, nothing to install.

When you do this, the address bar starts with file:// instead of https://. The browser below opened this example from a file and was asked what kind of address it had:

Chapter 1

What is HTML?

What the letters mean, who made it, when, why, and who looks after it today.

  1. 1.1HTML describes, it does not calculate

The short answer

HTML is the set of labels you put around content to say what each part is.

MDN, the main reference for web developers, puts it like this: HTML "is the most basic building block of the Web. It defines the meaning and structure of web content."

Source: MDN: HTML

What the letters mean

LetterWordPlain meaning
H THyperTexttext with links that take you to other pages (MDN: "text containing links that connect web pages to one another")
MMarkuplabels you put around content, like <h1> around a heading
LLanguagea fixed set of those labels, with rules for using them

What markup looks like

Below, <h1> and </h1> are labels around the words My trip to Goa. They tell the browser "this is the main heading". The browser then shows it big and bold. You never see the labels themselves.

<h1>My trip to Goa</h1>
<p>We went in December.</p>

Checker says
No errors or warnings.

Rule 1.1HTML describes, it does not calculate

HTML has no maths, no decisions and no memory. It only labels content. That is why people call it a markup language, not a programming language.

✓ Works
<p>2 + 3</p>
What the browser shows
Checker says
No errors or warnings.

Why: The browser shows exactly the characters you typed. Working out 2 + 3 is a job for a programming language like JavaScript or Python.

Who made it, and why

HTML was made by Tim Berners-Lee at CERN, a physics research lab in Europe, as part of the World Wide Web. CERN says the web "was originally conceived and developed to meet the demand for automated information-sharing between scientists".

  • March 1989: he wrote the first proposal for the World Wide Web.
  • By Christmas 1990: he had built "html, http and URL" and the first web server, browser and editor (called WorldWideWeb).
  • info.cern.ch was the world's first website, running on a NeXT computer at CERN.
  • August 1991: he announced the software on internet newsgroups.
  • 30 April 1993: CERN made the source code free to use (royalty-free).
  • 1994: he moved to MIT and founded the W3C (World Wide Web Consortium).

Source: CERN: A short history of the Web · CERN: World Wide Web at 35 · CERN: The birth of the Web

Who looks after HTML today

HTML is written down as a standard: one long document that says what every label means, so all browsers draw pages the same way.

  • Apple, Mozilla and Opera started a group called the WHATWG to keep developing HTML.
  • In 2019 the WHATWG and the W3C "signed an agreement to collaborate on a single version of HTML going forward".
  • That version is called the HTML Living Standard. It keeps being updated instead of getting new version numbers. Older tutorials call it HTML5; today it is just HTML.

The standard opens with: "HTML is the World Wide Web's core markup language."

Source: HTML Living Standard: introduction

Why learn HTML first

  • Every web page is built on it. CSS and JavaScript work on top of the HTML.
  • All you need is a text editor and a browser, which you already have.
  • You see the result the moment you refresh the page.

Your first page, and how mistakes behave

Make a page, open it, and learn the one thing that makes HTML different from Python: the browser never shows an error.

  6. Change a word, save, then refresh the browser (Cmd + R on Mac, Ctrl + R on Windows) to see the change.

Rule 2.1The file name must end in .html

The ending of the name tells the browser what kind of file it is. Only .html (or .htm) makes it read the labels.

✓ Works

<p>This is my first web page.</p>
What the browser shows

✗ Breaks: the same text saved as hello.txt
<h1>Hello</h1>
<p>This is my first web page.</p>
What the browser shows

Why: A .txt file is treated as plain text, so the browser shows every character, labels included. No error is shown either way.

Rule 2.2The browser fixes mistakes without telling you

Python stops and prints an error. A browser does the opposite: it guesses what you meant, repairs the page, and shows something. So a page can look almost right and still be wrong.

Below, the <b> (bold) label is never closed. The browser does not complain. It quietly carries the bold on into the next paragraph.

✓ Works
<p><b>Hello</b></p>
<p>World</p>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<p><b>Hello</p>
<p>World</p>
What the browser shows
What the browser built
<p><b>Hello</b></p><b>
<p>World</p></b>
Checker says
Error: End tag “p” seen, but there were open elements. (line 1)
Error: Unclosed element “b”. (line 1)
Error: Element “p” not allowed as child of element “b” in this context. (Suppressing further errors from this subtree.) (line 2)
Error: End tag for  “body” seen, but there were unclosed elements. (line 2)

Why: The browser had to decide where the bold ends. It chose to keep it going, and wrapped the second paragraph in a new <b> that you never wrote. You can see that in what the browser built, which is not what you wrote.

How to find mistakes: the W3C checker

Because the browser stays silent, you check your page with a checker (also called a validator). It reads your HTML and lists every mistake, like Python's error message does.

  1. Open validator.w3.org/nu.
  2. Choose file upload and pick your .html file, or choose text input and paste your code.
  3. Click Check. A clean page says there are no errors or warnings.

Every Checker says box in this book came from that same checker (the Nu HTML Checker), run on the example.

How to read a checker message

PartExampleWhat it tells you
TypeError or WarningAn error breaks the rules. A warning is advice you should usually follow.
MessageUnclosed element “b”.what is wrong, naming the label
Placeline 1the line in your file (this book counts lines in the example you see)

See what the browser built

Right-click anywhere on your page and choose Inspect. The panel that opens shows the page as the browser built it, after its repairs. Compare that with your file to spot where it guessed.

View Page Source (also in the right-click menu) shows your file exactly as you wrote it.

In Python, spaces at the start of a line change the meaning. In HTML they do not. People indent HTML only so it is easier to read.

Chapter 3

Tags, elements and attributes

The grammar of HTML: how labels open and close, how they sit inside each other, and how to add extra information to them.

  1. 3.1A closing tag has a / before the name
  2. 3.2Tag names must be real HTML tags
  3. 3.3Tag names are not case-sensitive, but write them in lowercase
  4. 3.4Close tags in the reverse order you opened them
  5. 3.5Some elements have no closing tag
  6. 3.6Attributes go in the opening tag, as name="value"
  7. 3.7Put attribute values in quotes

  9. 3.9Every opening quote needs a closing quote

Three words, one picture

  • A tag is a label name in angle brackets: <p>.
  • An element is the opening tag, the content and the closing tag together: <p>Hi</p>.
  • An attribute is extra information written inside the opening tag: href="about.html".

Rule 3.1A closing tag has a / before the name

The closing tag repeats the name, with / first. It marks where the element ends.

✓ Works
<p>This is <b>important</b> news.</p>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<p>This is <b>important<b> news.</p>
What the browser shows
What the browser built
<p>This is <b>important<b> news.</b></b></p>
Checker says
Error: End tag “p” seen, but there were open elements. (line 1)
Error: Unclosed element “b”. (line 1)
Error: Unclosed element “b”. (line 1)

Why: Without the /, the second <b> opens another bold instead of closing the first. Bold never ends, so news. is bold too.

Rule 3.2Tag names must be real HTML tags

HTML has a fixed list of tags. A name you invent is not an error the browser shows, but it means nothing to it.

✓ Works
<p>This is a paragraph.</p>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<paragraph>This is a paragraph.</paragraph>
What the browser shows
Checker says
Error: Element “paragraph” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.) (line 1)
Error: The “paragraph” element is a completely-unknown element that is not allowed anywhere in any HTML content. (line 1)

Why: It looks almost the same, which is the trap. The browser does not know <paragraph>, so it gives it none of a paragraph's meaning, and the checker calls it "a completely-unknown element". The real name is <p>.

Rule 3.3Tag names are not case-sensitive, but write them in lowercase

<P> and <p> are the same tag. Lowercase is the normal habit, and every example in this book uses it.

✓ Works
<p>lowercase tags</p>
What the browser shows
Checker says
No errors or warnings.
✓ Works
<P>UPPERCASE TAGS</P>
What the browser shows
Checker says
No errors or warnings.

Why: Both are correct and draw the same paragraph. Lowercase is the habit to build, because that is what you will read everywhere.

Rule 3.4Close tags in the reverse order you opened them

Elements sit inside each other like boxes inside boxes. The last one opened must be the first one closed.

✓ Works
<p><b><i>Bold and italic</i></b> then normal.</p>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<p><b><i>Bold and italic</b></i> then normal.</p>
What the browser shows
Checker says
Error: End tag “b” violates nesting rules. (line 1)
Error: No “i” element in scope but a “i” end tag seen. (line 1)

Why: <i> was opened last, so it must close first: </i></b>. Crossing them is like closing the outer box while the inner one is still open.

Rule 3.5Some elements have no closing tag

A few elements hold no content, so they have nothing to close. They are called void elements. The ones you will use most are <br> (line break), <img> (image), <hr> (line across) and <meta>.

✓ Works
<p>Line one<br>Line two</p>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<p>Line one</br>Line two</p>
What the browser shows
Checker says
Error: End tag “br”. (line 1)

Why: </br> does not exist. The browser happens to treat it as a <br>, so the page looks fine, but the checker still calls it an error.

! Trap: writing <br/> with a slash
<p>Line one<br/>Line two</p>
What the browser shows
Checker says
No errors or warnings.

Why: You will see <br/> and <img ... /> in older code. The checker accepts it and the browser ignores the slash. Plain <br> is the same thing, shorter.

Rule 3.6Attributes go in the opening tag, as name="value"

An attribute adds information to an element. It always goes inside the opening tag, after the tag name and a space.

✓ Works
<a href="index.html">Home</a>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<a>Home</a href="index.html">
What the browser shows
Checker says
Error: End tag had attributes. (line 1)

Why: Attributes are never allowed on a closing tag. The browser drops it, so this link goes nowhere.

Rule 3.7Put attribute values in quotes

A value with a space in it needs quotes, or the browser stops reading the value at the space. Quote every value and you never have to think about it.

✓ Works
<img src="sunset.png" alt="My sunset">
What the browser shows
Asked the browser
document.querySelector('img').alt
My sunset
Checker says
No errors or warnings.
✗ Breaks

What the browser shows
Asked the browser

My
Checker says
Error: Attribute “sunset” not allowed on element “img” at this point. (line 1)

Why: Without quotes, the value ends at the space. alt became just My, and sunset turned into a second attribute that means nothing.

Rule 3.8Do not repeat an attribute on one element

Each attribute can appear once per element.

✓ Works
<a href="about.html">About</a>
What the browser shows

No errors or warnings.
✗ Breaks

Why: The browser keeps the first one and throws the second away, so this link goes to about.html.

Rule 3.9Every opening quote needs a closing quote

A missing closing quote makes the browser keep reading everything after it as part of the value.

✓ Works
<p><a href="about.html">About</a></p>
<p>Some more text.</p>
What the browser shows
Checker says

✗ Breaks

Why: The browser kept reading the href value, looking for the closing quote. There was none, so it read to the end of the file and threw the whole tag away. The link and everything after it vanished.

The first line switches the browser into its normal mode. MDN: "The only purpose of <!doctype html> is to activate no-quirks mode." Without it the browser uses quirks mode, where "layout emulates behavior in Navigator 4 and Internet Explorer 5", browsers from the 1990s.

Chapter 5

Headings and text

Headings, paragraphs, line breaks, bold and italic, and what the browser does with your spaces.

  1. 5.1There are six heading levels, h1 to h6
  2. 5.2Pick the heading level by meaning, not by size
  3. 5.3Text goes in paragraphs: <p>
  4. 5.4<br> breaks a line inside a paragraph
  5. 5.5<pre> keeps your spaces and new lines exactly
  6. 5.6A heading cannot go inside a paragraph
  7. 5.7<strong> means important, <em> means stressed
  8. 5.8Comments are notes the browser does not show

Rule 5.1There are six heading levels, h1 to h6

<h1> is the main heading of the page. <h2> is a section heading under it, <h3> a part of that section, and so on down to <h6>.

✓ Works
<h1>Heading 1</h1>
<h2>Heading 2</h2>
<h3>Heading 3</h3>
<h4>Heading 4</h4>
<h5>Heading 5</h5>
<h6>Heading 6</h6>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<h7>Heading 7</h7>
What the browser shows
Checker says
Error: Element “h7” not allowed as child of element “body” in this context. (Suppressing further errors from this subtree.) (line 1)
Error: The “h7” element is a completely-unknown element that is not allowed anywhere in any HTML content. (line 1)

Why: There is no <h7>. The browser shows its text as plain words, with no heading style at all.

Rule 5.2Pick the heading level by meaning, not by size

The number is the level in an outline, like chapter, section, sub-section. Screen readers let people jump between headings by level. If you only want smaller text, that is a job for CSS.

✓ Works
<h1>Goa trip</h1>
<h2>Day 1</h2>
<h3>Morning</h3>
<h2>Day 2</h2>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<h2>Day 1</h2>
<h3>Morning</h3>
What the browser shows
Checker says
Warning: This document has heading elements but none of them has a computed heading level of 1. (line 1)

Why: The checker warns when a page has headings but no <h1>. Every page should start its outline with one main heading.

Rule 5.3Text goes in paragraphs: <p>

Each <p> is one paragraph. The browser puts a gap above and below it.

✓ Works
<p>First paragraph.</p>
<p>Second paragraph.</p>
What the browser shows
Checker says
No errors or warnings.
! Trap: pressing Enter does not make a new line
<p>Roses are red.
Violets are blue.


HTML     ignores     extra spaces.</p>
What the browser shows
Checker says
No errors or warnings.

Why: The browser turns any run of spaces, tabs and new lines into one space. Your blank lines and extra spaces disappear. To start a new line use <br>; to start a new paragraph use a new <p>.

Rule 5.4<br> breaks a line inside a paragraph

Use it where the line break is part of the content, like an address or a poem.

✓ Works
<p>Roses are red.<br>
Violets are blue.</p>
What the browser shows
Checker says
No errors or warnings.

Rule 5.5<pre> keeps your spaces and new lines exactly

Inside <pre> (preformatted), the browser keeps every space and line break, and uses a fixed-width font.

✓ Works

Ravi    25
Meena   31</pre>
What the browser shows
Checker says
No errors or warnings.

Rule 5.6A heading cannot go inside a paragraph

A paragraph can hold text and small things like links and bold. It cannot hold a heading, another paragraph or other big blocks.

✓ Works
<h1>Menu</h1>
<p>Today we have chai.</p>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<p><h2>Menu</h2> Today we have chai.</p>
What the browser shows
What the browser built

Checker says
Error: No “p” element in scope but a “p” end tag seen. (line 1)
Warning: This document has heading elements but none of them has a computed heading level of 1. (line 1)

Why: When the browser met <h2> it closed the paragraph first. Look at what it built: an empty paragraph, the heading, then loose text and an extra empty paragraph from your </p>.

Rule 5.7<strong> means important, <em> means stressed

<strong> and <b> both look bold; <em> and <i> both look italic. The difference is meaning. The standard says strong "represents strong importance, seriousness, or urgency" and em "represents stress emphasis". Screen readers can use that meaning.

✓ Works
<p><strong>Warning:</strong> the floor is wet.</p>
<p>I said <em>tomorrow</em>, not today.</p>
What the browser shows
Checker says
No errors or warnings.

Source: HTML Living Standard: text-level semantics

Rule 5.8Comments are notes the browser does not show

Write <!-- to start a comment and --> to end it. Everything between is hidden from the page.

✓ Works

Chapter 6

Links and paths

Make text clickable, link to other sites and to your own files, and get the path right.

  1. 6.1A link is <a> with an href
  2. 6.2A link to another website needs the full address
  3. 6.3Paths use forward slashes /
  4. 6.4No spaces in file names
  5. 6.5Link to a part of the same page with #id

Rule 6.1A link is <a> with an href

<a> (anchor) makes a link. href is where it goes. The text between the tags is what people click.

✓ Works
<p>Read <a href="https://example.com">the example site</a>.</p>
What the browser shows
Checker says
No errors or warnings.

Why: The browser underlines link text and colours it blue by default.

! Trap: <a> without href is not a link
<p>Read <a>the example site</a>.</p>
What the browser shows
Checker says
No errors or warnings.

Why: Without href there is nowhere to go, so the browser draws plain text. The checker allows it, because <a> without href is valid; it is just not a link.

Rule 6.2A link to another website needs the full address

Start with https://. Without it the browser thinks you mean a file in your own folder.

✓ Works
<a href="https://www.google.com">Google</a>
What the browser shows
Asked the browser
document.querySelector('a').href
https://www.google.com/
Checker says
No errors or warnings.
! Trap: leaving out https://
<a href="www.google.com">Google</a>
What the browser shows
Asked the browser
document.querySelector('a').href
file:///your-folder/www.google.com
Checker says
No errors or warnings.

Why: The checker is happy, but the browser read www.google.com as a file name in your folder. Clicking it opens a file that does not exist.

Paths: links to your own files

A path is the route from the file you are in to the file you want.

You writeIt means
about.htmla file in the same folder
pages/about.htmlgo into the pages folder, then the file
../index.htmlgo up one folder, then the file

Rule 6.3Paths use forward slashes /

Web paths always use /, even on Windows where folders on your computer use \.

✓ Works
<a href="pages/about.html">About</a>
What the browser shows
Asked the browser
document.querySelector('a').href
file:///your-folder/pages/about.html
Checker says
No errors or warnings.
✗ Breaks
<a href="pages\about.html">About</a>
What the browser shows
Asked the browser
document.querySelector('a').href
file:///your-folder/pages/about.html
Checker says
Error: Bad value “pages\about.html” for attribute “href” on element “a”: Backslash ("\") used as path segment delimiter. (line 1)

Why: The checker rejects a backslash as a folder separator. Chromium quietly turned it into / here (look at what the browser was asked), but you should not rely on a browser fixing it.

Rule 6.4No spaces in file names

Use - or _ instead of spaces when you name files: my-trip.html, not my trip.html.

✓ Works
<a href="my-trip.html">My trip</a>
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<a href="my trip.html">My trip</a>
What the browser shows
Asked the browser
document.querySelector('a').href
file:///your-folder/my%20trip.html
Checker says
Error: Bad value “my trip.html” for attribute “href” on element “a”: Illegal character in path segment. Space is not allowed. (line 1)

Why: Spaces are not allowed in a web address. The browser turns the space into %20, which is easy to get wrong. Name files without spaces and the problem never comes up.

Rule 6.5Link to a part of the same page with #id

Give an element an id, then link to it with # and that id. Clicking scrolls to it. Each id may be used only once per page.

✓ Works
<h1>Our shop</h1>
<a href="#contact">Jump to contact</a>

What the browser shows

✗ Breaks

<p id="contact">Call us.</p>
What the browser shows
Checker says

Warning: The first occurrence of ID “contact” was here. (line 1)
Warning: This document has heading elements but none of them has a computed heading level of 1. (line 1)

Why: With two elements sharing one id, the browser jumps to the first and the second can never be reached.

Chapter 7

Images

Put pictures on the page, describe them for people who cannot see them, and size them.

  1. 7.1An image is <img> with src and alt
  2. 7.2Always write alt
  3. 7.3width and height are plain numbers, no px
  4. 7.4Images in a folder need the folder in the path

Rule 7.1An image is <img> with src and alt

src (source) is the path to the picture file. alt is a short description of it. <img> is a void element, so it has no closing tag.

✓ Works
<img src="sunset.png" alt="Orange sunset over green hills">
What the browser shows
Checker says
No errors or warnings.

Rule 7.2Always write alt

Screen readers read alt aloud to people who cannot see the picture, and the browser shows it when the picture fails to load. The checker requires it.

✓ Works
<img src="sunset.png" alt="Orange sunset over green hills">
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<img src="sunset.png">
What the browser shows
Checker says
Error: An “img” element must have an “alt” attribute, except under certain conditions. For details, consult guidance on providing text alternatives for images. (line 1)

Why: The picture still shows, so the mistake is invisible to you. It is not invisible to someone using a screen reader.

! Trap: a wrong file name shows a broken image
<img src="sunst.png" alt="Orange sunset over green hills">
What the browser shows
Asked the browser
document.querySelector('img').naturalWidth
0
Checker says
No errors or warnings.

Why: The checker cannot know which files you have, so it finds nothing wrong. The browser could not find sunst.png, so it showed a broken-image icon and the alt text. Asked for the image's real width, it says 0: nothing loaded. Check the spelling and the folder.

Rule 7.3width and height are plain numbers, no px

You can give an image a size in pixels with width and height. Write just the number.

✓ Works
<img src="sunset.png" alt="Sunset" width="120" height="75">
What the browser shows
Checker says
No errors or warnings.
✗ Breaks
<img src="sunset.png" alt="Sunset" width="120px" height="75px">
What the browser shows
Checker says
Error: Bad value “120px” for attribute “width” on element “img”: Expected a digit but saw “p” instead. (line 1)
Error: Bad value “75px” for attribute “height” on element “img”: Expected a digit but saw “p” instead. (line 1)

Why: The attribute only accepts a number. The browser happened to cope here, but the checker reports both values as errors.

Rule 7.4Images in a folder need the folder in the path

Keep pictures in an images folder and include the folder name in src.

✓ Works
<img src="images/sunset.png" alt="Sunset">
What the browser shows
Checker says
No errors or warnings.
! Trap: forgetting the folder
<img src="sunset.png" alt="Sunset">
What the browser shows
Checker says
No errors or warnings.

Why: The picture is in images/, but the path says the file is right next to the page. The browser cannot find it and shows the alt text.
