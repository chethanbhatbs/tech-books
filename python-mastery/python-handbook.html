Getting Started

How Python runs your code, and the two commands every program is built from: showing output and reading input.

Needs: nothingTeaches: running code · print · input · commentsThen you can: write and run small programs

ConceptWhat "running Python" means

Python is an interpreted language. You do not translate your program into the processor's native instructions yourself; you write plain text in a file ending in .py, hand it to a program called the interpreter, and it carries out your instructions one line at a time, top to bottom. There is no separate build step, so the cycle of write, run, look at the result, and adjust is fast. That speed is a real part of why Python is a comfortable first language.

You can feed the interpreter code in two ways. Save it in a file and run the whole file at once, which is how real programs are written and shared. Or start the interpreter in interactive mode, called the REPL, and type one line at a time, seeing each result instantly, which is perfect for trying an idea. A program talks to the world through two basic actions: print() sends text out to the screen, and input() reads a line the user types in.

Interpreter

The program named python that reads your .py file and runs it line by line. You never compile Python into a standalone app; the interpreter is always what runs it.

ExamplesCode you can run

Example 1.1 · Hello, World and reading a name
# save as hello.py, then run:  python hello.py
print("Hello, World!")              # send a line of text to the screen
name = input("What is your name? ")    # show a prompt, wait for the user, store the reply
print(f"Nice to meet you, {name}.")  # f-string drops the value of name into the text
Hello, World! What is your name? Ada Nice to meet you, Ada.

Read it top to bottom, exactly as the interpreter does. Line 2 prints. Line 3 pauses for input. Line 4 prints again, using the value collected on line 3.

Example 1.2 · Controlling how print behaves
print("a", "b", "c")           # several values, separated by spaces by default
print("a", "b", sep="-")      # sep= changes what goes BETWEEN the values
print("loading", end="...")  # end= changes what goes AFTER (default is a newline)
print("done")                  # so this lands on the SAME line as 'loading'
a b c a-b loading...done

By default print joins items with a space and ends with a newline. The sep and end options let you change both, which matters the moment you want output on one line.

Think about it

Before you read on, predict what each of these prints, and why:

  1. print("2" + "3") versus print(2 + 3)
  2. print("ha" * 3)

1. The first prints 23, because + between two strings glues them together. The second prints 5, because + between two numbers adds. The same symbol does different work depending on the types on either side, a theme you will see again and again.

2. hahaha. Multiplying a string by an integer repeats it. Ask yourself: what would "ha" * "3" do? (It is an error, because you cannot multiply two strings.)

Variables & Data Types

How a program remembers things, why a name is a label rather than a box, and the small set of types every value belongs to.

Needs: Module 1Teaches: assignment · types · conversion · namingThen you can: store any kind of value

ConceptNames, values, and types

A running program constantly needs to remember things: a user's name, a running total, a result it will reuse later. A variable gives a value a name so you can refer back to it. You create one with the equals sign, name on the left, value on the right, and from then on the name stands for that value.

Two ideas set Python apart. First, you never declare what kind of value a name will hold. The value carries its own type, and the same name can hold a number now and a string later. This is dynamic typing. Second, and more subtly, a variable is not a box that contains a value; it is a label tied to a value. When you write x = 5, the number 5 exists somewhere in memory and x is a tag pointing at it. Writing x = 7 does not alter the 5; it moves the tag to a different object. This picture matters because two labels can point at the very same object, which you will meet as a real bug in the Lists module.

Every value belongs to a type, which decides what it can do. The handful below cover nearly everything. A value of one type can often be converted to another, for instance turning the text "42" into the number 42, which you will do constantly because user input always arrives as text.

Variable

A name bound to a value. The binding is made by assignment (name = value) and can change at any time. The name does not contain the value; it refers to a value object in memory, and several names may refer to the same one.

Data Type

The category a value belongs to (int, str, list, and so on), which decides what operations it supports. Check it with type(value).

ExamplesCode you can run

Example 2.1 · Assigning, and inspecting the type
age = 28             # an int (whole number)
price = 19.99        # a float (has a decimal point)
city = "London"      # a str (text, in quotes)
print(type(age), type(price), type(city))   # ask each value its type
<class 'int'> <class 'float'> <class 'str'>

We never wrote the types. Python read them from the values themselves. The quotes are what make city text rather than a name.

Example 2.2 · Converting text into a number
reply = input("How many? ")   # input ALWAYS returns text, even if it looks numeric
count = int(reply)            # convert the text "4" into the number 4
print(count * 3)               # now multiplication does arithmetic
How many? 4 12

Drop the int() and count * 3 would give '444', because count would still be the string "4" and * repeats text. Converting at the boundary is the fix.

Edge CasesWhat goes wrong, and the error you will see

Edge Cases & Common Errors
int("3.5")        # int() only parses whole numbers, not decimals
# ValueError: invalid literal for int() with base 10: '3.5'

int("twelve")     # words are not digits
# ValueError: invalid literal for int() with base 10: 'twelve'

"5" + 3           # you cannot add a string and a number
# TypeError: can only concatenate str (not "int") to str

age                # using a name you never assigned
# NameError: name 'age' is not defined

Notice the two distinct error types. A ValueError means the value is the wrong shape (text that is not a number). A TypeError means the types do not fit the operation (string plus int). Learning to read which one you got tells you whether to fix the value or fix the operation.

Think about it

You write x = "5". Then you want to add 3 to it. There are two ways to make 8 happen and one way to make "53" happen. Work out all three before revealing.

Get 8: convert the text to a number first, int(x) + 3. Or convert the 3 the other direction is not it, because x + str(3) gives "53".

Get "53": turn the 3 into text and glue, x + str(3). The lesson: + needs both sides to be the same kind of thing, and you choose which kind by converting.

Numbers & Math

Two number types, seven operators, the two divisions that confuse everyone, and why 0.1 + 0.2 is not 0.3.

Needs: Module 2Teaches: int · float · operators · math moduleThen you can: do any calculation

ConceptIntegers, floats, and the operators

Python has two everyday number types. An int is a whole number, and remarkably it has no size limit, so 2 ** 1000 gives an exact answer with three hundred digits. A float is a number with a decimal point, used for measurements and fractions. The two mix freely, and the result rises to the more general type, so an int plus a float is a float.

The operators are mostly familiar, with two that deserve attention. Division with / always gives a float, even when it divides evenly, so 6 / 2 is 3.0. When you want a whole-number quotient use floor division //, and its partner modulo % gives the remainder. Those two answer questions like "is this number even?" and "how many full hours are in these minutes?". For anything beyond arithmetic, the math module supplies roots, rounding, and constants.

Integer and Float

An int is a whole number of unlimited size. A float is a number with a fractional part, stored in fixed memory and therefore approximate. Use int for counting and indexing, float for measurement.

ExamplesCode you can run

Example 3.1 · The seven operators
print(7 + 2)    # 9    add
print(7 - 2)    # 5    subtract
print(7 * 2)    # 14   multiply
print(7 / 2)    # 3.5  TRUE division → always a float
print(7 // 2)   # 3    FLOOR division → drops the fraction
print(7 % 2)    # 1    MODULO → the remainder
print(7 ** 2)   # 49   power
9 5 14 3.5 3 1 49

The two to memorise are / (always a float) and // with % (whole quotient and remainder). Mixing them up is the single most common numeric slip.

Example 3.2 · Even-or-odd, and the math module
n = 17
print(n % 2 == 0)        # False → 17 leaves remainder 1, so it is odd

import math                  # bring in the math toolkit
area = math.pi * 5 ** 2      # pi × radius squared
print(round(area, 2))        # round to 2 decimal places
False 78.54

The x % 2 == 0 test for evenness is everywhere in programming. import math unlocks pi, sqrt, and dozens more.

Edge CasesWhat goes wrong, and the surprises

Edge Cases & Common Errors
10 / 0            # dividing by zero is undefined
# ZeroDivisionError: division by zero

0.1 + 0.2        # floats are approximate, so this is NOT 0.3
# 0.30000000000000004

round(2.5)         # surprise: rounds to the nearest EVEN number
# 2     (not 3, this is 'banker's rounding')

10 + "5"          # number plus text never works
# TypeError: unsupported operand type(s) for +: 'int' and 'str'

The float result is not a bug; it is how all computers store decimals. Compare floats with math.isclose(a, b) rather than ==, and for money use decimal.Decimal("0.1"). The round(2.5) == 2 surprise trips up nearly everyone the first time.

Think about it

You have total_minutes = 137. Without looking below, how would you get "2 hours and 17 minutes" using only // and %? Then ask: why does 137 // 60 give the hours and 137 % 60 give the minutes?

hours = 137 // 60 → 2, and minutes = 137 % 60 → 17. Floor division asks "how many whole 60s fit?" (the hours), and modulo asks "what is left over?" (the minutes). Together they always reconstruct the original: 2 * 60 + 17 == 137. This pairing is how you break any quantity into a larger unit and a remainder.

Strings

Text as an ordered sequence: how to index it, slice it, format it with f-strings, and why you can never change one in place.

Needs: Module 2Teaches: indexing · slicing · methods · f-stringsThen you can: manipulate any text

ConceptAn ordered, unchangeable sequence of characters

A string is a piece of text written inside quotes, single or double, it makes no difference. It is an ordered sequence of characters, which means every character has a position, called an index, starting at 0, and you can pull out one character or a whole range. Because text is everywhere in real programs, strings carry a rich set of built-in methods for searching, cleaning, splitting, and reassembling.

One property shapes everything else: strings are immutable. You cannot change a character inside an existing string. Every operation that seems to modify a string actually builds and returns a brand new one, leaving the original untouched. So s.upper() hands you a new uppercase string; if you want to keep it you must capture it with s = s.upper(). The modern way to build text from values is the f-string: put an f before the opening quote and write expressions inside braces.

String

An immutable, ordered sequence of characters, written in quotes. Immutable means it can never change in place; operations that transform it return a new string. Reach characters by index (s[0]) and ranges by slice (s[1:4]).

ExamplesCode you can run

Example 4.1 · Indexing and slicing
s = "Python"
print(s[0])     # 'P'      index 0 is the FIRST character
print(s[-1])    # 'n'      negative counts from the end
print(s[0:3])   # 'Pyt'    from 0 up to (NOT including) 3
print(s[2:])    # 'thon'   leave the end off → to the end
print(s[::-1])  # 'nohtyP' step of -1 → reversed
P n Pyt thon nohtyP

The slice [start:stop] stops before stop, which is why s[0:3] gives three characters, not four. The reversal trick [::-1] is worth memorising.

Example 4.2 · f-strings, splitting, and joining
name, score = "Ada", 91.5
print(f"{name} scored {score:.1f}")  # :.1f → one decimal place
print(f"{1234567:,}")              # :, → thousands separators

parts = "ada,bob,carol".split(",")   # text → list, breaking on commas
print(parts)
print(" & ".join(parts))            # list → text; join is called on the SEPARATOR
Ada scored 91.5 1,234,567 ['ada', 'bob', 'carol'] ada & bob & carol

split and join are inverses and do a huge share of real text work. The quirk to remember: you call join on the separator string, handing it the list.

Edge CasesWhat goes wrong, and the error you will see

Edge Cases & Common Errors
s = "Python"
s[0] = "J"          # strings are immutable → you cannot assign to a character
# TypeError: 'str' object does not support item assignment

s[10]              # reaching past the end
# IndexError: string index out of range

s.upper()           # this does NOT change s; the new string is thrown away
print(s)            # still 'Python', you forgot to capture the result
# Python

The silent trap is the last one: s.upper() looks like it works but changes nothing, because strings are immutable and the new string was never stored. Write s = s.upper(). The first two raise loud errors; this one fails quietly, which is worse.

Think about it

You want to capitalise the first letter of "hello" to get "Hello", but s[0] = "H" raises an error. Given that strings are immutable, how can you build "Hello" instead?

You build a new string from pieces: "H" + s[1:] gives "Hello". You take the slice after the first character and glue a new first character on. (Python also gives you s.capitalize() for this exact job.) The key insight: you never edit a string, you assemble a new one.

Booleans & Operators

True and False, the comparisons that produce them, the logic that combines them, and the surprising rule that every value is already either true or false.

Needs: Module 2Teaches: comparison · logic · truthinessThen you can: express any condition

ConceptTruth, comparison, and truthiness

A boolean is one of two values, True or False. They are the answers to yes-or-no questions, and every decision a program makes rests on one. You rarely type them directly; you produce them by comparing values with == (equal), != (not equal), and <, >, <=, >=. To build bigger conditions you combine booleans with and, or, and not.

Here is the idea that surprises newcomers and quickly becomes indispensable: every value can act as true or false, not just real booleans. Zero, the empty string, and empty containers count as false; everything else counts as true. This is truthiness, and it lets you write if name: to mean "if the name is not empty". A second surprise follows from it: and and or do not return True/False, they return one of the actual operands, which is what makes x = value or default a clean way to supply a fallback.

Boolean & Truthiness

A boolean is True or False. Truthiness is the rule that any value can stand in for a boolean in a condition: 0, 0.0, "", [], {}, and None are "falsy"; everything else is "truthy".

ExamplesCode you can run

Example 5.1 · Comparing and combining
age = 20
has_ticket = True
print(age >= 18 and has_ticket)   # and → BOTH must be true
print(age < 13 or age > 65)      # or → EITHER being true is enough
print(1 <= age <= 30)            # chained: reads "age is between 1 and 30"
True False True

Read the operators aloud and they say what they mean. The chained comparison 1 <= age <= 30 is a Python convenience most languages lack.

Example 5.2 · Truthiness and the "or" default
username = ""                  # an empty string is FALSY
display = username or "Guest"  # or returns the first truthy value
print(display)                  # 'Guest', because "" was falsy
print(bool(""), bool("hi"), bool([]), bool([0]))
Guest False True False True

Note the last value: [0] is truthy. A container is truthy when it is non-empty, no matter what is inside it. The single zero does not make the list falsy.

Edge CasesThe traps that produce wrong answers

Edge Cases & Common Errors
if x = 5:            # using = (assign) where you meant == (compare)
# SyntaxError: invalid syntax. Maybe you meant '==' ?

bool("False")         # the TEXT "False" is a non-empty string → truthy!
# True   (this surprises everyone)

bool(" ")             # a single space is a non-empty string → truthy
# True

1000 is 1000        # 'is' tests SAME OBJECT, not equal value, do not use it for numbers
# may be True or False depending on Python, use == instead

The dangerous ones are silent. bool("False") is True because it is a non-empty string, so checking user input by truthiness alone can accept the literal word "False". And is compares identity, not value; use == for values and reserve is for None.

Think about it

A program reads a setting as text and does if user_setting: to decide whether it is "on". The user types the word False. What happens, and why is it a bug? How would you check it correctly?

user_setting is the string "False", which is non-empty and therefore truthy, so the branch runs and the setting is treated as on, the opposite of what the user meant. Truthiness tests emptiness, not meaning. The correct check compares the value explicitly, for example if user_setting.lower() == "true":. The lesson: truthiness is for "is there anything here?", not for interpreting the content.

Lists

The workhorse collection: ordered, changeable, sliceable, and the place where the label-not-a-box idea finally bites.

Needs: Modules 2, 4Teaches: mutation · slicing · comprehensions · aliasingThen you can: store and process many values

ConceptOrdered and mutable

So far each name has held a single value. A list holds many values in order under one name. It is the workhorse of Python: a to-do list, the lines of a file, the rows of a table all live naturally in lists. You write one in square brackets, and it may hold any types, even mixed.

Two properties define a list. It is ordered, so every item has a position you reach by index, and slicing pulls out ranges exactly as with strings. And it is mutable, meaning you can change it in place after creation: add, remove, replace, sort. That is the sharp difference from strings, which are frozen once made. Because building a new list from an old one is so common, Python offers a one-line form called a list comprehension you will use constantly.

List

An ordered, mutable sequence of values, written in square brackets [1, 2, 3]. Ordered means items keep their position and are reached by index; mutable means the list can be changed in place after it is made.

ExamplesCode you can run

Example 6.1 · Changing a list in place
tasks = ["email", "lunch"]
tasks.append("call")     # add one item to the END
tasks.insert(0, "wake")  # add at a given position (the front here)
tasks.remove("lunch")    # delete the first item equal to "lunch"
print(tasks)              # the SAME list object, now changed
['wake', 'email', 'call']

Each method changes the existing list; none returns a new one. That is what "mutable" means, and it is why you do not write tasks = tasks.append(...).

Example 6.2 · The list comprehension
nums = [1, 2, 3, 4, 5, 6]
squares = [n * n for n in nums]           # transform EVERY item
evens   = [n for n in nums if n % 2 == 0]  # KEEP only some items (add an if)
print(squares)
print(evens)
[1, 4, 9, 16, 25, 36] [2, 4, 6]

Read it as a sentence: "n times n, for each n in nums". The optional if filters. This single line replaces a four-line loop that appends to a new list.

Edge CasesThe errors, and the famous aliasing bug

Edge Cases & Common Errors
xs = [1, 2, 3]
xs[5]                 # no index 5 exists
# IndexError: list index out of range

xs.remove(99)          # 99 is not in the list
# ValueError: list.remove(x): x not in list

# The aliasing bug: = does NOT copy a list
a = [1, 2, 3]
b = a                  # b is the SAME list, not a copy (two labels, one object)
b.append(4)
print(a)               # [1, 2, 3, 4], changing b changed a!
# [1, 2, 3, 4]

The first two raise loud errors. The third is the silent classic, and it is exactly the label-not-a-box idea from Module 2: b = a ties a second label to one list. Mutate through either name and both see it. To get an independent copy, ask for one: b = a.copy() (or a[:], or list(a)).

Think about it

You want a 3-by-3 grid and write grid = [[0] * 3] * 3. You set grid[0][0] = 9 and find that three cells changed, not one. Before revealing, work out why, connecting it to the aliasing bug above.

[[0] * 3] * 3 does not make three separate rows. The outer * 3 repeats the same inner-list object three times, so all three rows are one shared list with three labels on it, the aliasing bug in disguise. Changing one row changes all three. The fix builds three independent rows with a comprehension: grid = [[0] * 3 for _ in range(3)]. This is one of the most instructive bugs in the language.
